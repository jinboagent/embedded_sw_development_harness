The problemAgents don't lack intelligence. They lack institutions.

A human team accumulates rules in onboarding docs, review habits, and tribal memory. An agent team starts every session from whatever it reads. Without structure, you get:

📜 Rules that die with the chat

The convention you established on Tuesday is gone by Thursday — every session re-negotiates it, and agents drift apart.

🧪 "Verified" without proof

Agents state confidence fluently. Without transcripts, "it works" is a vibe, and regressions hunt you later.

🕳 Unauditable history

Commits like fix stuff, merges without manifests, diagrams silently drifting from the code they explain.

Every element of this kit exists because one of those failures happened for real in the source project — and the fix proved itself over months.

The philosophySeven principles

Constitution, not chatRules live in small files agents load every session.
Evidence or it didn't happen"Verified" means a transcript. Nothing else counts.
One feature · branch · manifestEvery merge lands a FEATURES index row.
Commits are documentsWhat / Why / How / Verification — enforced by a hook.
Registered diagramsEvery chart has an ID, a hash, and a drift checker.
Status is a pointerLATEST.md points; snapshots are append-only.
Context is a budgetLoad the constitution + the one spec in play.

The loopHow a working session flows

The agent never "remembers" a rule — it re-reads one. It never "believes" a fix — it re-runs one.

AI-specific, document-drivenDocuments are the programming interface

When the executor is an LLM, documents stop being documentation. Output is multiplicative — model capability × context quality — so the highest-leverage engineering act is writing the documents the code is generated from. And every correction loop ends in a document, not a memory.

The ritualThe life of a feature

Nothing lands on main except through this path — and a year later you can answer what was promised, what was proven, and where is the transcript for any line of code.

Context economyWhat the agent actually loads

This is why the harness is tiered: an agent editing feature X needs the constitution plus spec X — not the whole archive. History lives one hop away, keyed by feature and date.

What's in the boxFive folders, plain files

agent-context/

AGENTS + CLAUDE entry-point skeletons, the agent-memory template, and the ignore-file / context-tier strategy.

git-workflow/

Feature-branch policy, BRANCH / FEATURES manifest templates, the commit standard, and the commit-msg hook that enforces it.

harness/

The three-tier tree: constitution (00-global-context), feature specs (01-features), process reports + evidence rules (02-knowledge).

templates/

Feature spec, Unity C unit tests, status snapshots, tests README, quickstart, learning journal, root README, .gitignore, bug tracking + fix reports.

tools/

check_charts.py — the ASCII-chart drift checker — plus the chart-registry template.

skills/

Six standard-format agent skills: tmux-esp32 workflow, chart governance, evidence gate, matplotlib diagrams, Medium articles, pre-publish audit — copy into any agent's skills dir.

Get startedOne minute to take it

Copy the kit into any project

cp -r embedded-agent-kit/{agent-context,git-workflow,harness,templates,tools} /path/to/project/

# then: fill the {{PLACEHOLDERS}}, and once per clone —
git config core.hooksPath git-workflow/githooks

# seed the chart registry with your existing diagrams —
python tools/check_charts.py --scan

Full 12-step adoption checklist, the day-to-day rhythm, and a "where to look when" table are in the repo's README.md. Skip anything your project doesn't need — the kit is modular by design.

Why it holds upDecisions and their reasons

DecisionWhy
Markdown, not a frameworkAgents read files natively; zero install, zero lock-in, diff-able in git.
Hook-enforced commitsThe source project audited 47 free-form commits: 46 had drifted. Conventions decay; a 39-line hook doesn't.
Templates, not scriptsYou keep authorship — the kit shapes judgment, it doesn't automate it away.
Append-only status & evidenceHistory you can edit is history you can't trust.
Chart registry + checkerDiagram drift is invisible until it misleads; a hash makes it a build failure.
Tiered context loadingContext is the scarce resource; the design spends it deliberately.

ProvenanceField-tested, then reviewed

Extracted from an ESP32-S3 BLE bridge firmware project where four LLM agents (ZCode, Claude, DeepSeek, Qwen) built six stages of features under this workflow — every merge gated by hardware tests, every claim carrying a transcript. The kit was then independently reviewed by another agent, whose additions (bug tracking, quickstart, learning journal, five defect fixes) were folded in after re-review. The document-driven doctrine was sharpened against Tencent QQ Music's Harness Engineering write-up (2026) — an independent arrival at the same principles, at platform scale.

The kit eats its own cooking: the diagrams in its README are registered in its own chart registry and verified by its own checker — python tools/check_charts.py reports them clean.
